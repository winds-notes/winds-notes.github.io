# Architecture — WiNDS Notes

## Runtime
The site runs as **static HTML/CSS/JavaScript**, with no bundler or mandatory backend. An optional Node.js 22+ same-origin server provides persistent Google login and live previews. The root directory can be deployed unchanged to GitHub Pages. The `tools/dev-server.mjs` server is for development only.

## Selection transforms and input defaults (v66)

Stylus only defaults to enabled. An explicit checkbox choice is stored under winds-notes-input-preferences-v1 and restored independently of notebook data. Touch contacts pan or pinch in that mode; mouse editing remains available. Pencil detection never changes the preference. The missing-up/down recovery, palm guards and four non-passive Touch Event handlers are retained.

Selection callbacks retain an original item reference and sample coordinates. A three-CSS-pixel movement threshold avoids accidental edits from tap jitter. Animation frames prepare selection-preview.js layers once per gesture: a lower page layer, the selected object sprite, and a transparent upper layer. Subsequent frames restore only the swept rectangle and composite the moving sprite in the original stacking order. Resizing uses the existing aspect-ratio/rotated-anchor geometry; shape outlines retain their own width. Each canvas is capped at 4,194,304 pixels and 4096 pixels per side, independent of zoom. Released canvases are reset in an animation frame. If allocation fails or the optional module is unavailable, a clipped vector redraw provides a fallback.

Notebook objects remain unchanged during preview. Completed transforms enter the existing deferred interaction queue, wait for active input to finish, and produce one history snapshot and save notification. Moves translate the latest matching object to preserve intervening metadata and newly added ink. Account/page guards reject stale work. Pencil lost-release recovery preserves sampled movement; cancelled finger drags roll back. A selection generation prevents late area-selection results from replacing a newer selection. Select can leave a group by tapping another item. Hit tolerance is expressed in screen pixels; lines/arrows and closed figures use their actual geometry instead of an entire bounding rectangle.

The v66 service worker reuses unchanged versioned artwork from the previous cache and copies it into the new shell cache. Cold artwork downloads remain limited to two concurrent requests. The new preview module is included in the HTML, offline list, Node server allowlist, Docker copy and syntax checks. Native version 1 and account workspace keys are unchanged.

## Rendering and Pencil input
`app.js` maintains notebook/page state and two core drawing canvases: `#pageCanvas` for committed page contents, `#inkCanvas` for live ink. While the Pencil moves, only newly received points are drawn. After the user stops writing, pending ink is composited; local persistence is delayed to avoid stalls. Pressure samples are recorded as `[x,y,pressure]`. Initial pen thickness and shape outline width are both 7; changing the default does not rewrite widths in stored/imported items.

**Critical fix:** Safari's default double-tap and Scribble gesture handling can swallow short consecutive Pencil strokes. `app.js` cancels non-passive touch events on the writing canvas, recovers missing pointer-down/up sequences, tracks palm touches and preserves pinch zoom. Do not remove these defenses.

`creative-tools.js` supplies the pure shape path/fill renderer and deterministic graphite grades. The same renderer is called from live strokes and export rendering, so saved and exported pages match editor ink. 

Artist materials combine pressure-shaped curves, reusable pigment masks and paper-tooth patterns. Graphite grades have distinct width, density and edge softness; Charcoal uses broken, diffuse deposits; Color Pencil adds textured pigment; Ink Brush uses continuous filled pressure ribbons. Translucent pencil segments meet without internal round-cap overdraw. Work is incremental and capped at 96 deposits per new curve. Small default material masks are prepared at module load; custom colored-material masks are prepared on color selection and held in a bounded cache. Imported colors can initialize their masks during page rendering. No brush setup is added to the Pencil pointer handlers.

Texture is derived from material and stroke geometry rather than object IDs, so native imports can re-key IDs without changing its appearance. Artist items retain `tool:'artist'`, `grade`, color, size and pressure data, with optional `flow` (default 1) controlling deposition; native format version 1 is unchanged. Artist Studio groups 25 materials into Graphite, Ink and Pigment, with live size/flow previews. New technical, fountain/marker and textured pigment profiles live entirely in the creative renderer. Original profiles retain their texture; reduced-flow ink avoids internal round-cap stacking. Input code only copies the scalar flow into a new Artist draft. See `ARTIST_STUDIO.md`.

Animation-frame callbacks invoke pending-ink painting without passing the RAF timestamp as a finalize flag; only explicit stroke completion draws the tail. Regular pen curves use filled ribbons with continuous pressure widths and rounded caps, with bounded sampling per new segment. Rendering lives in `creative-tools.js`; the Pencil event recovery, touch suppression and idle persistence path are unchanged.

## Drawing data
Pages have an `items[]` array. Examples:

```json
{"type":"shape","id":"shape1","kind":"star","x":100,"y":100,"w":120,"h":120,"color":"#2b2d4c","size":3,"fillColor":"#f8d575","fillOpacity":0.7}
```

```json
{"type":"stroke","id":"stroke1","tool":"artist","grade":"2B","color":"#343b48","size":3,"points":[[100,100,0.4],[101,103,0.5]]}
```

Only closed shapes are filled. `fillColor:null` means outline only. An older file with neither `fillColor` nor `grade` still works; `native-file.js` sets safe defaults when importing. Square and Circle are their own `kind` values with locked proportions during dragging.

Images may have an optional `crop:{x,y,w,h}` rectangle in normalized source coordinates. An absent crop means the full image. `src` retains the original embedded image; the shared renderer uses the cropped source rectangle for the editor, thumbnails and exports. Cropping updates the displayed bounds while retaining the visible content's position. The on-page crop overlay uses its own pointer capture and maps edge and corner movements into unrotated source coordinates. Its draft is separate from the image. Apply records one undo snapshot, and Cancel discards the draft. Native format version 1 remains unchanged.

Images, stickers and shapes may also have an optional `rotation` in clockwise degrees, normalized to `[0,360)`. Missing rotation means zero. Rendering and selection outlines rotate around the object's center through the same canvas transform. Selection and resize hit tests inverse-transform pointer coordinates; resize/crop positioning keeps the retained content or opposite corner fixed in page coordinates. The rotation handle captures its own pointer and paints the changed region in animation frames. Releasing the handle commits one edit. Existing undo snapshots and workspace serialization retain the angle in native format version 1.

## Local and cloud storage
`app.js` stores notebook metadata and pages separately in IndexedDB; `localStorage` is the fallback. Guest and Google account workspaces use different store names. `cloud-drive.js` authorizes a user through Google Identity Services, saves its JSON workspace in that user's Google Drive and can retrieve it after reconnect. Explicitly shared notebooks use a separate per-notebook Drive folder and edit history. Account databases remain isolated; no private workspace file is shared.

Google sign-in requires a configured OAuth Web client ID, authorized JavaScript origin, enabled Drive API, requested scopes and suitable consent-screen publishing status. Access tokens must not be committed or stored as source files. Drive sync is idle/explicit; drawing remains usable offline.

Each account has a browser-persistent session record in localStorage, including its verified profile, short-lived access token and absolute Google expiry. This removes the dependency on another open tab: a fresh tab or browser restart can reverify and use a still-valid token. sessionStorage preserves each existing tab's account choice; restoring an older account tab does not change the last account explicitly selected elsewhere. A BroadcastChannel exchange remains a fallback for older tab sessions. No account IndexedDB names or native-file versions change. Static hosting cannot renew expired Google access automatically.

The optional same-origin Node server enables ongoing authorization. `server/google-auth.mjs` implements an OAuth authorization-code flow with state, PKCE and offline access. The server verifies the Google subject and email, issues an opaque HttpOnly/Secure/SameSite cookie, and keeps each account's refresh credential in an AES-256-GCM encrypted file outside the website. Account-specific session requests renew expired access tokens under a per-session lock and return only short-lived access credentials. Browser code never receives refresh credentials; in server mode it does not persist access tokens to localStorage. The cookie and encrypted store survive tab closure and process restarts. This file store supports one server process; multiple instances require a shared transactional store.

Server renewal and startup cloud sync use idle timers; neither adds work to Pencil handlers. A server outage retains the account and local workspace, then retries automatically. If server recovery finishes after writing starts, a workspace change waits until idle. Google revocation requires new authorization while retaining local notes. `/auth/` responses use `no-store` and bypass the service worker.

Automatic Drive sync uses the app's `syncIdleDelay` bridge: local persistence and cloud processing wait for a 2.5-second writing/editing pause and for dirty pages and writes to settle. A completed local save queues cloud work on the next timer turn, without an additional debounce delay. The 2.4-second ink composition and palm guards are unchanged. It rechecks before and after network awaits, before JSON parsing, before merging and before snapshot serialization/upload. Active input is rechecked after one second so completion does not inherit a long retry delay. Pinch zoom, inline text and image-crop editing also defer automatic storage/cloud work. If writing resumes during a remote merge's IndexedDB save, its canvas/UI refresh is deferred and scoped to that workspace; input state and the current stroke remain intact. The Pencil event handlers, live composition and palm/gesture suppression are unchanged.

Visible, idle retrieval polls on a 1-second cadence measured from the start of the previous sync, subtracting time spent on requests and processing. Checks remain sequential, with a minimum 100 ms delay after a check that exceeded its interval; input deferral and failure retries have separate scheduling so neither is confused with normal polling. Opening an account, online, window focus, pageshow and visible-document events queue an immediate idle-guarded check. After discovering the workspace, polling uses `files.get` with only the required metadata fields, bypassing the dated-backup search and HTTP caching. A missing/trashed workspace is rediscovered; other API errors retain the known file and retry without creating duplicates. Workspace discovery and the explicit dated-backup browser use separate app-property queries. Completed uploads broadcast an account-scoped change hint; matching tabs check their own authorized Drive file immediately, respecting automatic-sync pause and all writing guards. Drive `modifiedTime` avoids downloading an unchanged workspace, and local save versions avoid uploading it again. The app bridge can return a merge report containing `changed` and `needsUpload`. A remote-only merge saves locally without reporting a new local edit and marks the retrieved version synchronized after all idle checks pass. A union that retains local-only/newer notebooks or deletion markers still requires an upload. Default boolean merge results and save notifications are retained for older callers. Incoming notebooks that already belong to the final merge avoid another deep comparison; only retained local notebooks need comparison against the remote copy. Pending edits remain queued across upload failures or saves that finish during an earlier upload; failure retries retain their existing 45-second delay. Offline/hidden tabs defer work. Automatic sync defaults to enabled and preserves explicit per-account pause preferences. The Drive dialog reports the last successful upload, without adding controls or work to the writing toolbar.

Automatic cycles prioritize the active shared notebook, then process the private workspace, then perform one rotating background shared-notebook operation. Shared discovery is queued and joins one newly discovered notebook per automatic pass; explicit manual synchronization still checks all notebooks. Discovery failures keep their own backoff so they cannot postpone private workspace checks. Shared synchronization saves its outbox durably, reads the current notebook version, and writes merged edits to the same Drive file. An ambiguous upload is reconciled against the latest saved version before retry. Input and account checks remain before/after every await. Background notebooks remain automatic but can take longer than the open notebook.

The Drive dialog's optional Sync details panel records this tab's successful workspace checks, received changes, uploads and completed-cycle time. These ephemeral timestamps reset on account-session changes and are not sent as telemetry or persisted. Only expanded, visible details update; account buttons retain the existing stable UI-state guard.

The Drive dialog separates background polling from explicit-action busy state. Unchanged account/control state does not rewrite the dialog on every poll, and background requests do not disable sign-out or account switching. Explicit Drive actions clicked during a check queue behind it. A new account session aborts the previous Drive request and resets operation ownership; late responses and finalizers cannot update the new session or clear its busy state.

Logout removes the selected account's browser/server credentials, records a durable account logout stamp and broadcasts invalidation. Storage events also stop authorization when tab messaging is unavailable. Suspended sessions and delayed responses cannot restore credentials issued before logout. Offline server logout is queued and processed before accepting the next server session. Other account sessions remain independent; affected tabs stop Drive access while keeping local notes on screen until the user changes workspaces. Setup and origin-migration requirements are in `PERSISTENT_LOGIN.md`.

## Per-notebook sharing

The library card menu exposes Share and Delete as separate actions. `notebook-sharing.js` creates a dedicated folder and a validated single-notebook seed, then grants the named Google account writer access to that folder. It never grants permission on the private workspace file. The invitation includes an app URL with the folder ID; access always requires the invited account's Google authorization. Pending URLs survive an OAuth redirect in sessionStorage. Folder discovery is limited to this app's marker and runs at most once a minute; known notebooks are checked during idle sync.

`shared-notebook-model.js` flattens notebook metadata, page order, page metadata and items into stable locations. Per-location non-cryptographic fingerprints detect local changes; they are not used as security credentials. The baseline and outgoing edit batches live in optional `_sharing` notebook metadata inside the existing account database. Outgoing batches are saved before upload. Both editors write the same Notebook.json file. Stable batch IDs and deterministic replay merge independent changes, including changes recovered from overlapping pinned Drive revisions. Older edit files and v54 comment records are read on first open for migration. Same-object conflicts use timestamp/ID ordering. Private workspace retrieval cannot replace an already shared notebook's local baseline/outbox. Shared applies check save versions and input state before replacing data, and render only for the captured workspace after the durable write completes.

Each shared batch and final replay is validated through the native object validator while preserving stable IDs. Native exports strip `_sharing`; imports remain independent version-1 notebooks. Incoming content changes preserve safe append undo/redo but discard obsolete page snapshots that could erase collaborators' edits. A private ID collision is preserved as a separate private copy. Removing a shared notebook creates a local account tombstone and does not revoke or delete the shared Drive folder.

The design uses the existing Drive OAuth scope and idle guards, and remains the durable shared-data path. An optional relay adds temporary small-stroke previews without a millisecond-delivery promise. History and individual payloads are bounded. Setup, permission limitations and verification boundaries are in `NOTEBOOK_SHARING.md`.

## Optional live preview relay

`live-sync.js` queues outgoing item references and incoming raw event strings. At least 150 ms input-idle time is required before serialization, authenticated POST, parsing or preview rendering. A separate `#liveCanvas` paints confirmed-server packets without mutating notebook data, storage or undo. Static mode leaves its backing canvas at 1×1. Confirmed Drive items remove their preview; expiry/reset requests durable recovery. Private rooms derive from a cookie-verified Google subject; shared rooms verify the dedicated Drive folder's capabilities. Sign-out/automatic-sync pause close streams and clear queues. The service worker bypasses `/live/` as well as `/auth/`.

`server/live-relay.mjs` retains bounded room replay only in RAM (60-second window plus up to 15 seconds cleanup). It enforces origin checks, account/Drive permissions, packet/rate/stream limits and slow-reader closure. `server/start.mjs` streams SSE without whole-response buffering. One process and persistent encrypted authorization storage are required; neither Docker nor GitHub creates hosting automatically. See `REALTIME_SYNC.md` for deployment and coverage limits.

## Exports
`native-file.js` serializes editable notebook data as `.winds-notes` and validates imports. PDF, PNG and JPEG use the same `drawItem`/`drawPage` routines as the editor. Exports wait for active input to finish and PDF backgrounds to decode. A prepared download link remains available for five minutes and is cleared when accounts switch. The native file version remains 1; extra shape, artist and PDF-background fields are optional.

## PDF annotation
`pdf-import.js` lazy-loads locally bundled Mozilla PDF.js and its matching worker. Parsing runs during a modal import task; cloud merges and live-preview work defer while it is open. The importer captures the account and destination, checks them across asynchronous stages, supports page ranges/passwords and stages all pages before committing. It renders one page at a time, bounds raster memory and releases temporary canvases. Appending validates only imported pages and preserves existing page objects and sharing metadata. See `PDF_ANNOTATION.md` for limits and deployment files.

A page's optional `background` contains its embedded PDF-page JPEG, small thumbnail, raster dimensions, source filename and source page number. It is separate from `items[]`, so selection and erasing affect only annotations. Page dimensions preserve the source aspect ratio and rotation; PDF pages disable paper-template/orientation changes. The original PDF and password are not stored. Text, hyperlinks and form controls become pixels.

Native version-1 validation, backup import and shared history retain backgrounds. Validated backgrounds are frozen and cached; shared page fingerprints reuse an immutable background digest rather than repeatedly hashing its image data. The editor caches at most three full-size PDF images, retains small thumbnails separately, and guards asynchronous decode repaints against active writing and account changes. No PDF parsing, network operation, serialization or storage work was added to Pencil event handlers.

## Cache / deployment
The PWA uses `sw.js` for offline loading. ## Continuous writing workspace and deferred ink edits
`page-stack.js` owns page wrappers, nearby inactive previews and idle page activation while reusing the existing live canvas. Scroll activation preserves the viewport; explicit page navigation focuses the requested wrapper. Offscreen preview backing canvases are released. Preview decoding/composition defers during input, uses account/page generation guards, and performs no network requests. CSS zoom does not expand the writing canvas.

Erasing references the objects present at gesture start so queued work cannot delete freshly written ink. Pending edits defer cloud merges, storage, clipboard mutations and navigation; account/page checks discard stale work. ## Area eraser and preferences (v40)
Optional `erasures:[{rx,ry,points:[[u,v],…]}]` on each object stores brush radii and paths normalized to its unrotated bounds. `native-file.js` validates finite values, at most 2048 masks/2048 points per path/200000 total mask points per object, and preserves masks on every existing type. The native version remains 1. Clipboard/shared model validation uses the same schema.

`creative-tools.js` renders a masked object onto one bounded reusable transparent canvas, applies round swept paths using `destination-out` there, and composites the result. It never erases directly from the paper/neighboring objects. Separate passes form a union instead of an even-odd clip, preserving overlaps. Masks follow normalized geometry; cropping remaps them into the new crop. The common `drawItem` wrapper covers editor, preview, clipboard PNG and all exports. Late image decoding schedules account-scoped idle repainting.

Deferred erase jobs append masks to objects present at contact start and recheck geometry/account/page across awaits. Consecutive queued gestures merge masks onto the latest matching item instead of losing a gesture after the first replacement. One snapshot covers all affected objects. Network/storage/input guards and Pencil recovery are unchanged.

The main Eraser button and E shortcut select All objects before preparing the preview. The settings arrow opens the panel with the current target. `winds-notes-eraser-preferences-v1` stores size and the last explicit target in localStorage. Tool activation uses the saved size. No account key or token handling changes. Source pixels/text remain in editable native/Drive data underneath the masks; rendered exports show the erased result.


## Deferred edit recovery and asset consistency (v41)
`commitDeferredItems` stages item replacement and painting before scheduling a save. A paint/selection failure restores the previous item array, selection and undo/redo; queue finalization clears the pending count. The shared mask surface resets compositing/alpha between objects, resizes through a one-pixel-wide intermediate to avoid allocation spikes, retries null 2D contexts with smaller dimensions and falls back when getTransform is absent. A selection-preview allocation failure leaves the selection usable without its bitmap.

HTML and the offline pre-cache use matching versioned URLs for app, creative tools, native validation and interaction geometry, avoiding older cached dependencies during an update. No private workspace, account, OAuth or native schema changes.


## Live eraser feedback (v42)
`eraser-preview.js` is a visual layer around the deferred area-mask job. Tool/target changes or idle preparation build one bounded protected-background Canvas (at most 4,194,304 pixels, smaller allocation retries) and a 96-unit grid of candidate bounds. In Ink only mode the protected cache includes non-ink objects; paper and fixed PDF backgrounds are always protected. Account/book/page, non-eraser content revision, dimensions and target scope each cache. Leaving the tool releases its surface; account/library changes reset transient data. Missing contexts safely fall back to deferred erasing.

Input appends points and queues an animation frame. Frames copy clipped round swept regions from the protected cache onto the page Canvas and retain object-relative transient masks for later repainting. They do not scan every notebook object, serialize, persist or access the network. Candidate lookup uses the prepared grid. A frame processes at most 64 segments and checks elapsed time against 4 ms between segments; an individual segment can exceed that budget. The cursor clears only its previous bounding rectangle.

`drawItem` merges transient masks into temporary item views without modifying stored objects. Full repainting first flushes preview metadata outside active input. Starting handwriting disables old queued pixel patches so fresh ink cannot be wiped by a prior gesture. Deferred commit removes transient masks and performs the existing atomic durable edit, using the same cache while only erase masks change. Cancellation, failed commits and a finger gesture changing to pinch clear the relevant preview; palm contact preserves active Pencil input. Actual geometry, undo/redo and saving retain their idle guards. Native format, account keys and OAuth handling are unchanged.

## Storage transitions and idle synchronization (v57)

Explicit forced saves wait for any active storage transaction before flushing newer dirty pages. Workspace activation is sequential: finish edits, persist the current account, open/read the next account, then release the original database. Failed saves keep the current account open; failed target reads restore its database and library. Startup and activation share counted UI locks so overlapping sign-in cannot permanently disable the controls.

Storage errors are distinct from an uninitialized workspace. Failed/aborted reads, malformed fallback storage and missing referenced pages reject instead of triggering a blank-library write. A modal startup recovery action retries by reloading without clearing website data. A blocked database open rejects, and late successful connections are closed without assigning them to another account.

An unchanged shared notebook records the current book reference, local save version and known batch count after a successful sync. Later polls still check Drive permissions and revision metadata and retain periodic revision recovery, but skip full validation, fingerprints and history replay when the local version, batch count and head coverage agree. Any local edit, incoming batch, overwritten head, outbox entry or failed attempt retains the full guarded reconciliation path.

Image/native imports wait for interaction idle and validate their destination after asynchronous reads. Backup downloads, remote renders and Drive restores recheck their account after saving. Image insertion preserves PNG transparency and rejects decoded images exceeding the existing clipboard image-pixel limit.

## Closed-area color filling (v59)

Closed-area filling uses the current fill color and opacity; v61 makes its tool selection persistent (see below). Passive capture observers collect tap coordinates while the ordinary Pan tool continues handling navigation. Pointer callbacks schedule a later task; they do not run flood-fill, serialization, network or storage work. Drags and multiple touch contacts do not trigger fills, and palm contacts do not cancel a Pencil tap. Original drawing/Pencil handlers and non-passive Touch Event suppression remain unchanged.

Built-in closed shapes receive optional fillColor/fillOpacity without altering their outline. Hand-drawn boundaries are rendered onto a transparent page-sized surface at model resolution, independent of zoom. Notebook ruling and PDF backgrounds are excluded. `boundary-fill.js` finds the connected transparent region, rejects areas reaching a page edge, and produces a cropped transparent PNG. Work yields regularly and rechecks interaction idle, account/page identity and save version; navigation, tool changes or intervening edits cancel stale work. Automatic and manual incoming sync defer while a fill operation is processing.

A hand-drawn fill is an ordinary image with optional `boundaryFill:true`, inserted underneath existing ink. It supports existing image rendering, erasing, movement, rotation, clipboard and exports. Native format version remains 1; older files without the marker still import. Existing fills are excluded from boundary detection. Recoloring replaces a layer only when its position, dimensions and complete alpha mask match, preventing opacity stacking or replacement based only on a bounding rectangle. Undo snapshots and shared edit replay retain the optional marker. All deployable files, including the new local script, must be uploaded together.

## Persistent Fill selection and export-test isolation (v61)

The primary Fill button selects the tool immediately and remains selected. A separate caret opens settings, opacity and the mandala library. An inline color input and the ordinary toolbar/custom palettes update fill color without changing the pen color. Continue filling dismisses settings without leaving the tool; another tool or Escape ends the mode. Existing shape-border editing is available through the caret.

Selection and processing are separate flags. Idle selection does not block automatic Drive checks; only an actual queued/running fill operation defers incoming data. Each tap captures its page scope, color and opacity without rendering or serialization in the callback. Up to 32 pending taps are processed serially outside input callbacks; each operation checks the latest version when it starts. A changed workspace/page cancels old work. The mode remains selected after completion or an open-boundary error. Undo/Redo and incoming edits refresh the version used by the following tap.

Unexpected `Untitled notebook` downloads were traced to browser verification exporting generated test notes through Chrome's default Downloads folder, rather than to filling or automatic synchronization. The local verification scripts now disable downloads by default, and explicit download checks use an isolated `/private/tmp` directory. In-page prepared blobs may be inspected without downloading. Production exports remain explicit actions; no notebook data or user files were deleted by the fix.
